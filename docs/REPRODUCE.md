# REPRODUCE.md — what reproduces on a clean checkout, and where the boundary is

This project's reported figure (`results/figures/pareto_frontier.png`) and table
(`results/tables/summary.csv`) reproduce **deterministically on CPU** from a clean checkout via
`make all`. Two sources are NOT reproducible from a clean checkout — backbone training and the raw
Galaxy-Zoo catalogs — because they need a GPU and ~160 MB of upstream data. We state that boundary
honestly here rather than implying the whole pipeline runs locally.

## TL;DR

```bash
make env      # venv + pinned deps (incl. pytest-timeout)
make test     # fast CPU suite, green in ~40s (GPU backbone-training tests are marked `slow`, deselected)
make all      # = arms → eval → report : regenerates the figure + summary.csv on CPU (~2 min)
```

## What `make all` regenerates (CPU, deterministic)

`all: arms eval report`.

- `make arms` re-runs HCT (M3), L2D-Okati (M4), L2D-Mozannar (M5) over the **frozen** backbone,
  writing `results/*_predictions.parquet` + `results/*_operating_points.csv`.
- `make eval` recomputes shared metrics + bootstrap CIs and writes `results/tables/summary.csv` +
  `results/figures/pareto_frontier.png` (+ their `.manifest.json`).

Determinism is enforced by seed=0 everywhere (`src/haidc/seed.py`), the bootstrap seed=0, and the
rater-draw seeds `[0,1,2,3,4]` (figure manifest `config`). **Check it:**

```bash
make eval && shasum results/tables/summary.csv
make eval && shasum results/tables/summary.csv   # identical hash across the two runs
```

A re-run of `make all` leaves `git status` clean: the regenerated `*_predictions.parquet`, figure,
and `summary.csv` are byte-identical to what is committed.

## The committed frozen interface (these make CPU reproduction possible)

Everything `make all` consumes is committed (forced past `.gitignore`'s `*.parquet` / `data/**`
rules — see the negation block in `.gitignore`):

| Artifact | Size | Produced by | Consumed by |
|---|---|---|---|
| `data/split_manifest.json` | small | M1 split (seed=0, 70/15/15) | all arms + eval (frozen split, CLAUDE.md inv. #2) |
| `data/label_table.parquet` | 84 KB | M1 label build (raw Willett/Kaggle + crosswalk) | HCT urns + eval ground truth |
| `results/backbone_scores.parquet` | 12 KB | M2 backbone (GPU) | AI-alone + HCT binarization |
| `results/backbone_embeddings.parquet` | 69 MB | Stage-B export (GPU) | L2D-Okati(learned) + Mozannar |
| `results/*_predictions.parquet`, `*_operating_points.csv` | small | the arms (M3–M5) | eval (regenerated by `make arms`) |

> The 69 MB embeddings parquet is committed deliberately so the L2D arms re-run on CPU without a
> GPU. GitHub warns on files >50 MB; this is under the 100 MB hard limit.

## The reproducibility boundary (NOT reproduced by `make all`)

Two upstream stages produced the frozen artifacts above and are **out of `make all` on purpose**:

1. **Backbone training + embedding export (GPU/Colab).** `make backbone` trains the Okati-faithful
   scratch ResNet-50 (3×224×224, `Linear(2048,2)`+`LogSoftmax`, `NLLLoss`; 120 epochs) and exports
   scores + 2048-d embeddings. It ran on a Colab T4 (CUDA 12.8, torch 2.11+cu128; see
   `results/backbone_run.json`), reproduced via **`notebooks/m2_colab.ipynb`**. It needs the raw
   training images (`data/raw/images_training_rev1/`) and a GPU; its outputs are committed as the
   frozen interface. The CPU tests that exercise this path are marked `slow` and deselected (see
   `tests/README.md`); run them on a GPU with `pytest -m slow`.

2. **Label-table / split build (raw catalogs).** `make data` and `make verify-split` rebuild
   `data/label_table.parquet` from the raw catalogs — `data/raw/zoo2MainSpecz.csv.gz`,
   `zoo2MainPhotoz.csv.gz` (Willett 2013), `training_solutions_rev1.csv` (Kaggle), and the
   `data/galaxyid_to_dr7objid.csv` crosswalk (~161 MB total, **not committed**). `verify-split`
   recomputes the split hashes and asserts they match the committed `split_manifest.json` (the
   confound guard for CLAUDE.md invariant #2). To run either target, place the raw catalogs under
   `data/raw/` and the crosswalk at `data/galaxyid_to_dr7objid.csv` (provenance:
   `docs/HANDOFF.md` §5, §11).

In short: `make all` reproduces the **report** from the frozen interface on CPU; reproducing the
frozen interface itself requires a GPU (stage 1) and the raw catalogs (stage 2).
